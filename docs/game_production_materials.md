# Dyadic Force 游戏制作素材库

> 用途：集中整理项目的美术设计、关卡设计、交互反馈、UI、资产来源、制作流程与迭代经验。  
> 本文面向游戏制作复盘、作品集、论文系统设计章节和后续版本开发。  
> 研究方法与实验数据的完整材料见 [`academic_paper_materials.md`](academic_paper_materials.md)。
> 可直接取用的论文设计章节和图片副本见 [`paper_game_design/`](paper_game_design/README.md)。

## 1. 制作定位

### 1.1 游戏概念

两只猴子被约束在大球直径两端，共同推动球体穿过像素风自然场景。两人同向施力时球体前进，方向冲突时球体旋转或偏移。游戏通过分屏、惯性、碰撞、传送门和可撞门，把抽象的双人协调转化为直接可见的动作反馈。

### 1.2 制作目标

- 用简单输入形成足够丰富的双人互动；
- 保持轻松、自然、像素冒险的外观；
- 让合作规则尽量通过运动和反馈被理解；
- 避免将游戏制作成显眼的实验任务集合；
- 在美术与关卡层面复用有限素材，控制制作规模；
- 让关卡、物理和实验测量使用同一套世界结构。

### 1.3 当前内容范围

- 1 个教学关；
- 5 个正式关；
- 标题、实验录入、配对、校准、选关、暂停和结算界面；
- 双键盘与双手柄输入；
- 中英文 UI；
- 球体、猴子、碰撞、门、传送和触觉反馈；
- macOS 导出与应用图标。

## 2. 整体美术方向

### 2.1 视觉关键词

- 像素；
- 温暖自然；
- 童趣但不过度幼稚；
- 草地、水面、森林和木质结构；
- 清晰的轮廓与功能层级；
- 轻量伪 3D；
- 柔和弹性动效；
- 不暴露实验结构。

### 2.2 视觉层级

| 层级 | 内容 | 设计目标 |
|---|---|---|
| 世界底层 | 草地、水面、道路和场景分区 | 提供路线与空间背景 |
| 边界层 | 围栏、树、灌木、石头、枯木 | 形成可读通道与风险边界 |
| 玩法层 | 球、猴子、门、传送门 | 始终高于装饰的可读性 |
| 反馈层 | 阴影、闪白、粒子、震屏、箭头 | 解释运动、碰撞和状态 |
| 界面层 | HUD、菜单、提示和结算 | 支持任务，不遮挡核心动作 |
| 研究层 | 路段、扰动候选区、岔路确认线 | 后台不可见 |

### 2.3 美术约束

- 关卡中唯一新增的主要可见玩法对象是可撞门；
- 门复用现有木围栏图集，避免引入风格不一致的新资产包；
- 不新增实验区域、风险标志、停车台、信号灯或奖励宝箱；
- 不在世界中显示同步率、领导者、受扰玩家或补偿指标；
- 关卡长度来自路线与自然重复，不来自机关堆叠；
- 研究标注不应成为场景装饰。

## 4. 球体视觉设计

### 4.1 伪 3D 方案

游戏仍是 2D，但球体不能看起来像一张平面圆图。当前方案通过：

- 圆形精灵；
- 球面法线近似；
- 姿态矩阵 `ball_rot`；
- 纹理随物理旋转更新；
- 独立球体阴影；
- 边缘明暗与遮罩；

制造球体在平面场景中滚动的立体感。

### 4.2 为什么不直接旋转圆形贴图

直接旋转整张圆形图只能产生“唱片转动”，无法同时表达：

- 沿任意方向滚动；
- 球体表面经过视野；
- 平移方向与自转轴的关系。

shader 方案使视觉姿态能够跟随物理角速度，而不是仅绕画面法线旋转。

### 4.3 阴影设计

阴影承担三项功能：

1. 将球体与地面分离；
2. 说明球体仍位于同一地面层；
3. 在分屏和复杂植被中维持轮廓。

历史审计曾发现球、猴和旗子的阴影透明度与偏移不统一。制作时应维护统一规则：

- 光源方向一致；
- 阴影偏移一致；
- 大小按物体接地范围而非精灵外框决定；
- 闪白材质不得作用到 Shadow 节点，否则会出现白色方块。

## 5. 猴子角色与协作可读性

### 5.1 角色动画

现有猴子资产包含：

- idle；
- run；
- jump。

角色的首要制作任务不是展示复杂动作，而是说明：

- 当前玩家是谁；
- 当前施力方向；
- 猴子位于球体哪一侧；
- 球体与猴子的连接关系；
- 输入是否有效。

### 5.2 输入箭头

输入箭头从八方向吸附改为 360° 连续方向，原因是：

- 模拟摇杆具备连续方向；
- 八方向吸附会掩盖细微修正；
- 研究任务需要参与者看见自己的真实操作方向；
- 箭头也是玩家理解两股力关系的主要视觉语言。

### 5.3 分屏中的身份

- P1 位于左屏；
- P2 位于右屏；
- A/B 是实验身份，不等于固定 P1/P2；
- 画面提示必须避免将 P1/P2 误写成稳定参与者身份。

制作中应同时区分：

- 玩家座位；
- 输入槽位；
- 参与者编号；
- 屏幕位置；
- 猴子视觉颜色或标签。

## 6. 世界场景与环境美术

### 6.1 场景构成

当前环境主要由以下素材构成：

- 草地；
- 水面；
- 木围栏；
- 树；
- 灌木；
- 石头；
- 花草；
- 枯木；
- 地面箭头；
- 出生旗；
- 终点传送门。

### 6.2 自然分区

第 3–5 关在长路线中使用景物变化帮助玩家辨认位置。可采用：

- 林地；
- 岩地；
- 草甸；
- 深林；
- 水边；
- 门前开阔地；
- 难点后的恢复区。

分区的作用不是增加新机制，而是：

- 降低长地图中的迷失；
- 标记路线节奏；
- 让重复弯道不显得机械；
- 给玩家形成“已经走到哪里”的空间记忆。

### 6.3 地面箭头

早期实现曾让所有地面箭头朝右。在包含纵向与回转路线后，这会直接传达错误方向。

生产规范：

- 箭头必须沿局部中心线方向；
- 急转弯前不应让箭头指向墙；
- 岔路入口可不显示单一方向箭头，避免暗示“正确路线”；
- 箭头只用于导航，不标记刹车点、实验区或风险等级。

### 6.4 装饰与碰撞

- 装饰不得侵入球体主要行驶带；
- 视觉边界与物理边界应基本一致；
- 水面用于形成清晰不可通行区域；
- 树冠不能严重遮挡球体与猴子；
- 小石头不应成为不可见的卡球点；
- 难点后必须有恢复空间。

## 7. 传送门设计

### 7.1 功能目标

传送门同时承担：

- 终点识别；
- 停车目标；
- 靠近反馈；
- 成功演出；
- 场景转场。

### 7.2 历史失败方案

被否决的版本包括：

- 两条矩形光柱；
- 整个角色同步闪白；
- 角色直接缩小消失；
- 传送门动态抬高 z-index 遮住球；
- activation 填满整圆，吞掉内部漩涡；
- shader 中使用不允许的 `return`，导致白块或门消失。

这些问题不是“参数不够漂亮”，而是视觉结构与层级错误。

### 7.3 当前方向

- 独立 `TeleportFx` / `TeleportFxLayer`；
- 门体始终位于球下方；
- 靠近时门心和外缘逐渐点亮；
- 保留内部漩涡纹理；
- 传送演出与结果转场对齐；
- 触觉反馈逐步增强；
- 不让光效破坏球和角色轮廓。

### 7.4 制作原则

传送门应让玩家读出“停在这里完成”，而不是“高速撞进去”。因此亮度、声音、震动和计时反馈应鼓励靠近与稳定停留。

## 8. 可撞门设计

### 8.1 视觉语言

- 木质；
- 横跨道路；
- 无法绕开；
- 门柱复用 Sprout Lands 围栏；
- 成功时向两侧打开或破开；
- 失败时晃动并轻微反弹；
- 不显示数值门槛。

### 8.2 成功反馈

成功应包含：

- 门立即取消阻挡；
- 短促破裂动画；
- 尘土粒子；
- 适度震屏；
- 手柄震动；
- 清晰但不过长的通过窗口。

`gate_burst.gd` 使用 Pixel Adventure 1 的尘土粒子。

### 8.3 失败反馈

失败不扣血，避免新机制教学与生命惩罚叠加。反馈应说明“还需要重新组织”，而不是暗示碰撞系统出错：

- 门晃动；
- 球轻微反弹；
- 不出现受伤闪白；
- 不播放死亡级反馈；
- 同一次持续接触不重复刷反馈。

### 8.4 新手难度修正

历史设计采用三门递增，并让后续关卡直接复用最高档门。手柄新手试玩表明第一扇门已经接近主观难度上限。

近期制作调整：

- 教学关增加更容易的门；
- 正式门统一降低至原第一扇门级别；
- 第 3、5 关不再使用极高阈值门。

仍需：

- 双手柄新手试玩；
- 验证单人不能稳定通过；
- 验证双人无需多次失败即可理解；
- 检查门前助跑距离。

## 9. UI 视觉系统

### 9.1 页面体系

- 标题页；
- 设置页；
- 实验信息录入页；
- 配对页；
- 校准页；
- 选关页；
- 关卡 HUD；
- 暂停菜单；
- 结算页。

### 9.2 UI 设计原则

- 标题、正文、数字和操作按钮使用不同字体角色；
- 研究编号优先可读性，不能只追求像素装饰；
- 中英文需分别处理字号和描边；
- 重要按钮支持键盘与手柄；
- 保存路径等技术信息不直接堆在结算页；
- 实验模式和调试模式默认关闭；
- 调试控制不得出现在正式实验界面。

### 9.3 已解决的 UI 问题

| 问题 | 修正 |
|---|---|
| 选关页实验条件文字重叠 | 重排布局并明确最小尺寸 |
| A/B 编号可重复 | 实时查重并阻止继续 |
| 结算页路径显示不全 | 只显示保存状态与“打开文件夹” |
| 21 个物理滑条过多 | 精简为 8 个 |
| 调试滑条放在选关页 | 移入教学关内部 |
| 中文像素字体描边漏边 | 使用多层扩张描边 |
| 只读编号看起来可编辑 | 重做视觉状态 |
| 数字 `0/O/D`、`1/I/L` 难区分 | 编号改用 Atkinson Hyperlegible Mono |

### 9.4 关卡 HUD

HUD 需要同时表现：

- 剩余时间；
- 生命；
- 暂停入口；
- 第 4 关干扰状态；
- 教学步骤；
- 必要的输入提示。

第 4 关 HUD 的边界：

- 可以说明“本关存在干扰”；
- 可以在实际干扰时增强紫色反馈；
- 不显示受扰玩家；
- 不显示精确下次触发时间；
- 不使用“实验条件”字样破坏游戏语境。

## 10. 动效与反馈系统

### 10.1 弹簧动效

UI 和世界提示采用 `UiSpring` 类型的弹性运动。适用场景：

- 页面进入；
- 按钮焦点；
- 输入箭头；
- 提示弹出；
- 结算星级；
- 短促碰撞反馈。

原则：

- 弹性用于强调层级，不应让所有元素持续晃动；
- 关键实验数字不应因夸张弹性而难以读取；
- HUD 动效不能遮挡动作或干扰计时判断。

### 10.2 碰撞反馈

碰撞反馈组合：

- 球体视觉冲击；
- 猴子与球的动作变化；
- 相机震动；
- 伤害闪白；
- 生命变化；
- 手柄震动；
- 重碰撞时死亡爆裂。

碰撞类别需要区分：

- 普通障碍；
- 世界边界；
- 可撞门；
- 非伤害触发区。

### 10.3 死亡与重生

- 分级伤害；
- 生命以半心为最小显示单位；
- HP 清零触发球体爆裂；
- 重生演出后恢复控制；
- 正式关附加时间惩罚；
- 重生不能与扰动、触觉或旧输入状态叠加。

### 10.4 触觉反馈

事件型触觉用于：

- 扣血；
- 撞门；
- 配对或校准确认；
- 传送过程。

不使用：

- 持续移动微震；
- 每帧重新启动震动；
- 仅按速度差推断碰撞；
- 屏幕震动替代真实触觉验证。

## 11. 音频现状

当前仓库未发现 `.wav`、`.ogg` 或 `.mp3` 音频资产。

这意味着现阶段反馈主要依赖：

- 视觉；
- 相机震动；
- 手柄震动；
- UI 动效。

### 11.1 音频制作机会

后续可以补充：

- 球体滚动的速度分层循环；
- 木门失败碰撞声；
- 木门破裂声；
- 普通碰撞与伤害声；
- 生命损失提示；
- 传送门环境声与完成音；
- UI 确认、取消和焦点声；
- 第 4 关低强度干扰提示。

### 11.2 音频设计边界

- 第 4 关音效不能泄露受扰玩家；
- 不用倒计时音效提前暴露隐藏扰动；
- 高频碰撞声需防止连续接触刷屏；
- 音频必须能关闭或统一调节；
- 正式实验需固定音量和播放设备。

## 12. 关卡制作总则

### 12.1 单关单目标

每关只保留一个主要合作挑战：

| 关卡 | 主要能力 | 避免混入 |
|---|---|---|
| 教学 | 理解基础规则 | 正式难度、隐藏实验操纵 |
| 第 1 关 | 共同起步 | 急弯、路线选择、扰动 |
| 第 2 关 | 共同减速 | 门、分叉、输入扰动 |
| 第 3 关 | 弯道协调 | 路线选择、真实扰动 |
| 第 4 关 | 失衡补偿 | 窄道、门、分叉 |
| 第 5 关 | 路线选择 | 扰动、急弯、分支内门 |

### 12.2 路线设计

- 第 3–5 关采用样条路线；
- 不出现明显直角拐；
- 紧张段与恢复段交替；
- 宽度本身可以传达难度；
- 难点后保留重新组织空间；
- 长度来自自然路线，不要求重复折返刷时长；
- 中心线既服务布局，也服务数据分析。

### 12.3 球体尺寸与通道

球体直径约 88 px。历史设计给出的经验边界：

- 正常稳定通道不宜低于约 150–170 px；
- 第 3 关实测最窄约 176 px；
- 第 4 关更宽，实测最窄约 250 px；
- 第 5 关短窄支约 172 px，宽支约 200–208 px。

这些数值是设计与静态测量结果，不代表最终人类可玩性已验证。

### 12.4 难度来源优先级

优先：

1. 双方启动与制动时序；
2. 连续方向协调；
3. 惯性与弯道；
4. 路线取舍；
5. 可感知输入失衡。

避免：

1. 隐形碰撞；
2. 极窄缝隙；
3. 无提示规则变化；
4. 过高门阈值；
5. 为凑时长而强迫失败。

## 15. 制作迭代中的典型案例

### 15.1 传送门：参数修改无法挽救错误结构

早期多次试图通过亮度、光柱和白闪增强传送效果，但问题来自层级和形状本身。最终通过独立特效层、保留漩涡、控制 z-order 和重写演出解决。

**经验**：当反馈被评价为“比之前更糟”，应检查视觉结构，而不是继续堆参数。

### 15.2 L4/L5：换装饰不等于新关卡

初版复用了旧关卡骨架，只改变部分障碍和名称，被认为缺乏诚意。后续才用折返和螺旋拓扑区分。

**经验**：关卡差异应首先体现在路线拓扑和玩家决策，而不是美术皮肤。

### 15.3 UI 滑条：工具越多不代表调试越好

21 个物理滑条造成认知负担，最终精简为 8 个常用参数并移入教学关。

**经验**：开发工具也需要信息架构，应围绕调参任务组织，而不是暴露所有变量。

### 15.4 新手门难度：开发者输入形成偏差

键盘开发时门难度不明显，手柄新手却在第一扇门就受阻。

**经验**：制作验收必须使用最终设备、最终人数和目标熟练度。

### 15.5 记录卡顿：后台系统也属于玩家体验

同步派生分析导致通关/失败瞬间卡顿。

**经验**：数据、存档和导出都属于游戏制作范围；不可见系统仍会通过延迟影响反馈质量。

## 18. 可用于作品集或论文系统章节的制作总结

### 18.1 美术总结

Dyadic Force 以 Sprout Lands 的自然像素素材为基础，通过伪 3D 球体 shader、分屏构图、连续方向箭头、统一阴影和独立传送特效层建立核心视觉识别。美术生产遵循“实验结构后台化”的原则：除木质可撞门外，不增加显式实验装置，而是使用道路宽度、植被分区、水面分隔和恢复空间传达难度与路线。

### 18.2 关卡总结

关卡从早期 lane/gauntlet 模板逐步演化为五类合作任务。制作过程中两次重要纠偏分别是：否决仅靠换装饰扩展的 L4/L5 初版，以及依据手柄新手反馈降低门难度并把门教学前置。最终路线设计优先通过拓扑、惯性和双人时序制造难度，而不是通过极窄碰撞通道或隐藏规则。

### 18.3 制作方法总结

项目把自动布局测量、几何可达性、组件断言、实机设备检查和人工试玩视为不同层次的验收。历史问题表明，任何单一层次都不足以证明成品质量：测试通过的震动不一定真实起振，BFS 可达的路线不一定可玩，参数合理的门也可能对新手过难，而后台数据分析同样可能通过卡顿破坏关键反馈时刻。
