# 预实验标准操作程序（SOP）

本文件冻结当前单一流程：**单次可行性预实验（feasibility pilot）**，协议版本 `pilot-1.0`，原始 schema `3.2.0`。目标是验证流程、时长、可玩性、扰动可感知程度和数据完整性，**不检验扰动的因果效应**。

编号 `F01` / `F01A` / `F01B`（朋友）或 `S01` / `S01A` / `S01B`（陌生人）是 **假名化编号（pseudonymous IDs）**，不是匿名数据。采集站另记 `station_id`。编号映射、知情同意书与实验 CSV 必须分开保存。

## 1. 目的与非目的

本轮要回答：

- 现场流程能否一次走完，时长是否可接受。
- 设备、手柄、分屏与日志是否可靠。
- 五关是否可玩，失败/重开是否可解释。
- 第 3 关能否记录正常协调。
- 第 4 关是否出现预期真实干扰，以及干扰前 200 ms 局部基线能否算出补偿与恢复。
- 原始三表是否完整，跨组汇总是否可运行。

本轮**不做**：

- 显著性检验、功效分析或正式假设检验。
- 把第 3 关与第 4 关包装成严格对照。
- 宣称第 4 关相对第 3 关的差异完全由干扰导致（两关地图与任务不同）。
- 组间随机分配或 Baseline / Perturbation 全局分组。

## 2. 建议规模

- 先做 **6–8 个 dyad（12–16 人）**。依据是覆盖流程变异与异常类型，不宣称统计功效。
- 若连续两组仍出现新的阻断问题（无法完成、关键日志缺失、设备无法继续），再扩到 **10–12 个 dyad**。
- 停止扩组的条件：流程可重复执行，质量门槛达标，不再出现未登记的阻断类型。

## 3. 纳入、排除与偏离处理

预先定义，不因结果“难看”临时删数据。

**纳入**

- 成年人。
- 能理解双人合力任务，并在说明后完成教学/校准。
- 双方都能使用键盘或手柄完成五关中的操作。

**排除（预先登记，不进入正式分析集）**

- 设备故障导致无法完成标准流程，且无法在当场用备用设备恢复。
- 中途退出且未完成第 3 关与第 4 关中的任一关键关。
- 身份录入错误且无法在当次 session 内用同一 dyad 编号更正。
- 关键日志缺失：`session.csv` / `frames.csv` / `events.csv` 任一缺失，或无法对应 `session_id`。

**保留但标记偏离**

- 完成了流程但有中断、重试。
- 第 4 关干扰次数少于预期，但仍有 `trial_end`。
- 关系条件以外的现场备注（写入实验笔记，不写入游戏 CSV）。

**试次级质量标记（不自动排除整个 dyad）**

- `effective_sample_hz < 55`；
- `estimated_frame_drop_pct > 5%`；
- 试次内发生控制器断连。

这些条件由 `trial_results.csv.quality_flag` 自动标记。正式排除前仍需结合原始日志与现场记录复核，不得只按结果方向删试次。

`unspecified` 关系不得锁定，不得进入正式数据。现场必须选择陌生人 / 朋友。

## 4. 现场步骤与建议时长

每个 dyad **只完整做一遍**。不要按 Baseline / Perturbation 做两套五关。

| 步骤 | 建议时长 | 动作 |
|---|---|---|
| 说明与知情同意 | 5 分钟 | 说明任务、录像/日志范围、可随时退出；签署后才开实验模式。 |
| 录入组号与关系 | 1 分钟 | 研究员只输入数字序号；系统按本机采集站自动生成完整编号、参与者编号与左右侧别。 |
| 配对、教学与校准 | 3–5 分钟 | 双方认领设备，完成输入检测。 |
| 五个正式关 | 15–25 分钟 | 按选关顺序一次完成；第 3 关记正常协调，第 4 关固定真实干扰。 |
| 简短访谈 / 异常登记 | 3–5 分钟 | 可玩性、干扰是否可感知、中断与退出原因。 |
| 数据质检 | 2 分钟 | 确认当次目录已写出 `raw/` 三表，结算页无导出失败。 |

全程建议 30–45 分钟。记录中断、重试与退出原因。同一组重开应用仍使用同一 dyad 编号，不把该编号复用给其他组合。

## 5. 编号、侧别与填写示例

格式：

- 朋友组：`F01`，参与者 `F01A`、`F01B`
- 陌生组：`S01`，参与者 `S01A`、`S01B`
- 采集站：独立列 `station_id`（1、2、3…），不编进组号
- A/B **不随左右屏变化**；左右屏另记 `side_assignment`

系统规则：

- 每台电脑首次使用前，在标题页「设置 → 本站编号」配置一次采集站；设置会永久保存，并写入 `station_id`。
- 录入页只允许输入大于 0 的数字。输入 `1`、`01` 或 `001`，选朋友得到 `F01`，选陌生人得到 `S01`。
- 字母只来自关系，不能在录入键盘中输入。换关系会当场改字母：`F01` ↔ `S01`。
- 参与者由系统派生为 `F01A` / `F01B`，不能在游戏里改。
- 组号奇数：A=P1（左屏），B=P2（右屏）。组号偶数：A=P2，B=P1。侧别不能在游戏里覆盖。
- 两台电脑可以同时录入 `F01`；靠 `station_id` 区分，不要靠组号本身区分机器。

填写示例：

1. 采集站 1 的第一对朋友：输入 `1`，选朋友 → `F01` / `F01A` / `F01B`，奇数规则 A=P1。
2. 下一对陌生人：输入 `2`，选陌生人 → `S02` / `S02A` / `S02B`，偶数规则 A=P2。

这些编号是假名，不是姓名缩写。游戏数据不得承载姓名、联系方式或学号。时间戳属于间接标识，共享前按伦理要求处理。

## 6. 关卡解释边界

- **第 3 关**：记录正常协调（弯道、共同控制）。
- **第 4 关**：固定包含真实干扰；补偿与恢复用每次干扰前 200 ms 的局部基线计算。
- 两关地图和任务不同，预实验结果只用于流程、调参和描述性分析。
- 不得把 L3 与 L4 的差异写成干扰的因果效应，也不得据此做正式功效检验。

当前没有组间条件，也没有随机分组。方法学上这不是随机对照实验。

## 7. 质量门槛

预实验通过（可以讨论是否进入正式实验）需同时满足：

- 原始三表完整率 100%：每个纳入 session 都有 `raw/session.csv`、`raw/frames.csv`、`raw/events.csv`。
- `session_id` / `trial_id` 无冲突。
- ≥90% 的 trial 有 `trial_end`。
- 第 4 关有预期扰动事件（`perturb_on`），且 A/B 被扰动侧基本平衡（允许小样本波动，但需记录）。
- 纳入试次的 `quality_flag=ok`；非 `ok` 试次必须进入待复核/排除清单并说明处理。
- 重大设备/流程阻断率低于预设阈值：纳入 dyad 中因设备或流程无法继续的比例 **< 20%**。
- 记录所有偏离和排除。

未达标时先修流程或软件，再扩组；不要用事后挑选“好看”的组来凑数。

## 8. 数据结束流程

1. 运行 `tools/aggregate_experiments.gd`，生成 `_aggregate/`。
2. 核对 `aggregate_report.json`：纳入/跳过/错误 session，schema 必须全为 `3.2.0`。
3. 冻结并归档：协议版本 `pilot-1.0`、代码 commit、硬件/系统版本、排除清单、偏离笔记。
4. 编号映射表、同意书与 CSV **分开放**；映射表不进 session 目录，不进 git。
5. 再决定是否进入正式实验。正式实验需要另行冻结设计，不能直接沿用本预实验的探索性调参。

## 9. 学术规范对照

投稿或内部审计时，对照 ACM CHI 2026 与 APA JARS 至少记录：

| 项目 | 本预实验如何记录 |
|---|---|
| 伦理审批 / 豁免依据 | 实验笔记与伦理文件；不写入游戏 CSV。 |
| 招募与纳排标准 | 见第 3 节；实际排除写入排除清单。 |
| 知情同意 | 纸质或独立电子文件；与假名编号映射分开。 |
| 参与者流程 | 见第 4 节；一次完成，无组间条件。 |
| 分配规则 | 无随机分组。侧别按 dyad 奇偶自动分配。 |
| 偏离与排除 | 实验笔记 + `aggregate_report.json` 跳过原因。 |
| 缺失数据处理 | 见数据字典：空字段、删失状态、中断恢复只追加不改写。 |
| 硬件 / 软件 / 协议版本 | `session.csv` 的 `app_version`、`platform`、`protocol_version`；另记 commit 与设备型号。 |

补充材料与仓库在投稿时须去除机构和人员身份。

### 已具备的合规点

- A/B 稳定身份与 P1/P2 设备侧别分离。
- 原始 `raw/` 不可覆盖；结果可重算。
- 版本与阈值写入 `analysis_manifest.json`。
- 关系与协议使用受控枚举/版本字符串。
- 自动跨组汇总与 `aggregate_report.json` 审计。

### 必须避免的写法

- 把本数据称为“匿名数据”。
- 把 `unspecified` 关系写进正式分析。
- 把本方案写成随机对照或组间实验。
- 在 CSV 中保存姓名或联系方式。
- 把第 3/4 关差异解释为干扰的因果效应。

## 11. 现场怎么用（操作手册）

游戏只负责：编号、侧别、五关过程记录、结果重算。  
知情同意、编号映射、访谈、排除清单，都写在游戏外，见 [现场记录表](pilot_field_log.md)。

### 11.1 开实验前（做一次即可）

1. 用 Godot 打开本项目，或运行导出的游戏。
2. 标题页打开 **实验模式**（会写入设置，下次还在）。调试模式保持关闭，除非要调物理。
3. 点 **打开数据文件夹**，确认能进 `experiments/`。macOS 上：
   - 编辑器运行：`~/Library/Application Support/Godot/app_userdata/DyadicForce/experiments/`
   - 导出的 `.app`：`~/Library/Application Support/DyadicForce/experiments/`
4. 在游戏外准备三份独立文件，**不要放进上述目录，也不要进 git**：
   - 知情同意书
   - 编号映射表：`F01A` ↔ 同意书编号（不要写姓名进 CSV）
   - 每组一份 [现场记录表](pilot_field_log.md)
5. 记下手柄型号、系统版本、本仓库当前 commit。

### 11.2 每一组怎么走

顺序固定，只做一遍：

`标题（实验模式开）` → `录入组号/关系` → `配对` → `输入检测/校准` → `选关` → `教学关（建议）` → `第 1–5 关` → `访谈` → `打开数据文件夹核对`

**1. 说明与同意（约 5 分钟）**  
先签字，再开游戏。说明：会记录操作与时间戳，不是匿名；可随时退出。

**2. 录入（约 1 分钟）**

- 首次在每台电脑的设置中确认本站编号，例如第一台为 1、第二台为 2。
- 点「录入组号」，只输入 `1`，再选「朋友」或「陌生人」。朋友显示 `F01` / `F01A` / `F01B`，陌生人显示 `S01` / `S01A` / `S01B`。
- 下一组输入 `2`。另一台电脑可以同时录入 `F01`，靠 `station_id` 区分，不会混成同一组。
- 未选关系不能继续。换关系会当场改字母。
- 看自动分配：奇数 A=左屏 P1，偶数 A=右屏 P2。
- 点 **锁定并继续**。

同一组如果中途退出、重开应用：组内数字仍填同一个 `1`，关系选同一个，系统恢复为同一个 `F01` 或 `S01`。会新建一个 UTC 子目录，不算覆盖旧数据。不要把该编号给下一对参与者。

**3. 配对与校准（约 3–5 分钟）**

- 左屏 P1：`WASD` 或手柄 A 加入。
- 右屏 P2：方向键或另一只手柄 A 加入。
- 双方都在后进入输入检测。手柄做校准，键盘会显示无需校准。
- 谁坐左边由侧别决定，不是由谁先按键决定。A 始终是 `F01A` 那个人。

**4. 选关与五关（约 15–25 分钟）**

游戏**不会**强制按 1→5 播放，研究员要按这个顺序点：

| 顺序 | 关卡 | 现场记住 |
|---|---|---|
| 建议先 | 教学关 | 不限时，熟悉同向推 / 反向转 |
| 1 | 三门冲关 | 共同起步 |
| 2 | 折返原野 | 共同减速 |
| 3 | 林间弯道 | 正常协调参考 |
| 4 | 不稳小径 | 固定真实干扰；灯会亮 |
| 5 | 分叉小径 | 路线选择 |

每关结算后看有没有导出失败。成功就点下一关。重试可以，但要在现场记录表记一笔。不要为了“好看”重开第 4 关刷干扰。

**5. 访谈（约 3–5 分钟）**  
用现场记录表上的四个问题。不要把回答打进游戏。

**6. 当次质检（约 2 分钟）**  
回标题页 → 打开数据文件夹 → 进入 `station-1/dyad-F01/<刚才那个 UTC 时间>/`：

- `raw/session.csv`、`raw/frames.csv`、`raw/events.csv` 都在
- `results/trial_results.csv` 在
- 第 4 关玩过的话，`results/perturbation_results.csv` 通常也在；`events.csv` 里应有 `perturb_on`

### 11.3 全部组做完之后

在项目根目录：

```bash
godot --headless --path . --script res://tools/aggregate_experiments.gd -- \
  --root "$HOME/Library/Application Support/Godot/app_userdata/DyadicForce/experiments" \
  --out "$HOME/Library/Application Support/Godot/app_userdata/DyadicForce/experiments/_aggregate"
```

看 `_aggregate/aggregate_report.json`：纳入了几组、有没有跳过、schema 是不是全是 `3.2.0`。  
研究用 `_aggregate/trials.csv`，不要手工拼各 session 的 CSV。

然后冻结：协议 `pilot-1.0`、commit、设备/系统版本、排除清单。再决定要不要做正式实验。

### 11.4 软件不会替你做的事

这些不是故障，是刻意留在游戏外：

| 缺口 | 怎么办 |
|---|---|
| 不会提示下一组该填几 | 自己按 `1, 2, 3…` 递增，记在映射表 |
| 已有 `station-1/dyad-F01` 时不会警告 | 重开同号会新建 UTC 文件夹；换人必须换号 |
| 不能改 A/B 编号或左右侧 | 只按组号自动生成；坐错边就停下来改座位，不要改软件 |
| 选关不锁顺序 | 按上表人工点 1→5 |
| `session.csv` 没有 git commit、手柄型号 | 结束时写进冻结清单 |
| 没有访谈界面 | 用现场记录表 |
| 实验模式默认关 | 每次开局先看标题页开关 |

### 11.5 编号速查

| 你输入 | 关系 | 系统得到 | 默认左右 |
|---|---|---|---|
| `1` | 朋友 | `F01` / `F01A` / `F01B` | A 左 P1，B 右 P2 |
| `1` | 陌生人 | `S01` / `S01A` / `S01B` | A 左 P1，B 右 P2 |
| `2` | 朋友 | `F02` / `F02A` / `F02B` | A 右 P2，B 左 P1 |
| `12` | 陌生人 | `S12` / `S12A` / `S12B` | 偶数，A 在右 |
